3. **Open question on the *integer-cents vs decimal.Decimal* transfer**: `CtrlAltDevelop/ledger-service` likely uses integer-cents (the GitHub README mentions *ledger* discipline; charter §3.6 hard invariant requires `decimal.Decimal` for EUR-arithmetic to avoid binary-float rounding errors). 4. **Open question on the *transactional-outbox* primitive trigger**: the *transactional-outbox* primitive is most valuable when there is a downstream system that needs eventual consistency (e.g., a notifications queue, a billing system, an external accounting system). LE31 v1 has no downstream system today; the *transactional-outbox* discipline is over-engineered for the current v1 surface. The artifact is vocabulary-only; the implementation would require a real downstream system to exist.
5. **Open question on the *idempotency* middleware scope**: should the *idempotency* middleware apply to all FastAPI endpoints or only the close-bill + close-shift endpoints? The *idempotency* middleware adds latency to every request (hash + lookup); applying it universally is wasteful. The artifact is vocabulary-only; the implementation would require explicit endpoint-scope decision.
