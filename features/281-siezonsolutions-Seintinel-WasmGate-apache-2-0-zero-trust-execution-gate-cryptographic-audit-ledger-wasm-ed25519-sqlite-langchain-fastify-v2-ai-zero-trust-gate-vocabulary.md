## Open questions

1. **Who would ever run the offline verifier of a zero-trust-execution-gate-with-cryptographic-audit-ledger?** LE31 has exactly one stakeholder (the owner) who can just read the audit log directly; the *zero-trust-gate + ed25519-cryptographic-audit-ledger* may be over-engineering for a single-tenant single-operator scenario. **This open question may kill any future PR.**
2. **Charter §3.4 explicit sign-off needed**: the *zero-trust-execution-gate + Wasm-sandbox* surface is operator-tooling per charter §3.4 invariant, but the v2-AI control-plane is a new surface that requires explicit charter-decision before any PR.
3. **Ed25519 key management**: any v2-AI PR that adopts ed25519-signature must also adopt a key-management discipline. This is a non-trivial operational concern.
4. **Wasm-sandbox vs OS-sandbox**: the *Wasm-sandbox* is a software-level isolation primitive; a future v2-AI PR may want a stronger OS-level sandbox (e.g., Firecracker, gVisor) instead. The Wasm-sandbox is the vocabulary primitive; the actual sandbox choice is a v2-AI PR decision.
5. **sqlite vs Postgres**: the *siezonsolutions/Seintinel-WasmGate* repo uses SQLite for the audit ledger; LE31 v2-AI would use Postgres (charter §3.1 invariant). The *sqlite-backing* is a vocabulary primitive; the actual backing store is a v2-AI PR decision.
6. **OFF-STACK WARNING**: the *siezonsolutions/Seintinel-WasmGate* repo is written in **TypeScript**; LE31 v1 stack is Python+HTMX. A future v2-AI PR would need to port the *zero-trust-execution-gate + ed25519-signature + Wasm-sandbox* discipline to Python+FastAPI+SQLModel+Postgres.
