## Description

LE31 v1 today has no v2-AI surface. The `AllStreets/ONEXUS` repo (Apache-2.0, 4★/1⑂, 29358 KB substantial, in-window by `pushed_at` only, language: Python ✓) documents a **local-first-AI-agent-runtime + capability-arbiter + declared-manifest + earned-trust-scoring + immutable-audit-ledger + mcp-integration** pattern that LE31 v2-AI could adopt for any future autonomous-agent surface. The pattern is: (a) the agent runs locally (local-first-runtime); (b) every tool call clears a capability-arbiter that gates against a declared manifest; (c) every tool call is scored on earned trust; (d) every tool call is written to an immutable audit ledger; (e) the agent exposes MCP tools for external integration. The **capability-arbiter + declared-manifest + earned-trust-scoring + immutable-audit-ledger** discipline is the *charter §3.1 + §3.3 + §3.4* invariant applied to the *v2-AI-agent-tool-call* dimension. The *local-first-runtime* posture IS the *charter §3.7 on-device-AI-runtime* invariant applied to the *agent-execution* dimension (privacy-aligned for any future v2-AI surface that wants to keep the agent runtime on-device per charter §3.7). The *capability-arbiter* posture IS the *charter §3.4 capability-as-audit-gate* invariant applied to the *tool-call* dimension (a tool call is gated against a declared manifest; the *capability-arbiter* IS the *charter §3.4 capability-as-audit-gate* primitive). The *declared-manifest* posture IS the *charter §3.1 explicit-state-manifest* invariant applied to the *tool-call* dimension. The *earned-trust-scoring* posture IS the *charter §3.4 trust-scoring-as-auditable-test* invariant applied to the *agent* dimension (the agent earns trust over time based on its behavior; the *earned-trust-scoring* IS the *charter §3.4 trust-as-audit-evidence* primitive). The *immutable-audit-ledger* posture IS the *charter §3.3 append-only-ledger* invariant applied to *tool-call* dimension. The *mcp-integration* posture IS the *charter §3.4 mcp-control-plane* primitive.

## Open questions

1. **Who would ever run the offline verifier of a capability-arbiter + earned-trust-scoring + immutable-audit-ledger?** LE31 has exactly one stakeholder (the owner) who can just trust the agent directly; the *capability-arbiter + earned-trust-scoring* may be over-engineering for a single-tenant single-operator scenario. **This open question may kill any future PR.**
2. **Charter §3.4 explicit sign-off needed**: the *capability-arbiter + declared-manifest + earned-trust-scoring* surface is operator-tooling per charter §3.4 invariant, but the v2-AI control-plane is a new surface that requires explicit charter-decision before any PR.
3. **Earned-trust-scoring is OFF-§3.1 at v1**: LE31 v1 stores counts, not scores. Any v2-AI PR that adopts *earned-trust-scoring* must first get explicit charter §3.1 sign-off.
4. **Declared-manifest signing**: any v2-AI PR that adopts *declared-manifest* must also adopt a manifest-signing discipline (who can sign manifests, how are manifests versioned, how are manifest changes audited). This is a non-trivial operational concern.
5. **Local-first vs cloud deployment**: the *AllStreets/ONEXUS* repo runs the agent locally (charter §3.7 *on-device-persistence* invariant). A future v2-AI PR may want to run the agent in a cloud deployment instead; the *local-first* posture IS the *charter §3.7 on-device-persistence* invariant, but the *cloud-deployment* alternative requires explicit charter §3.7 review.
