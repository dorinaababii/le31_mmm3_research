## Data model

N/A (defer artifact; vocabulary-only; no schema today).

When the first v1 PR that adopts the *ESC/POS-byte-emit-to-device-queue + take-a-number-queue + USB-installer + single-binary-deploy + kitchen-ticket-printing-from-a-system-in-regular-use* discipline lands, the schema is:

```sql
-- Kitchen ticket is emitted as an ESC/POS byte string to a device queue.
CREATE TABLE kitchen_ticket (
    id BIGSERIAL PRIMARY KEY,
    order_id BIGINT NOT NULL,        -- foreign key to order table
    ticket_number INT NOT NULL,      -- take-a-number queue number
    byte_payload BYTEA NOT NULL,      -- ESC/POS byte string
    state TEXT NOT NULL,             -- 'queued' / 'printing' / 'printed'
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Take-a-number queue is the operator-facing surface when no phone-screen is available.
CREATE VIEW take_a_number_queue AS
    SELECT
        ticket_number,
        order_id,
        byte_payload,
        state,
        created_at
    FROM kitchen_ticket
    WHERE state IN ('queued', 'printing', 'printed')
    ORDER BY ticket_number ASC;
```
